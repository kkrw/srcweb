# SRC データフォーマット仕様書

## 概要

旧SRC形式のテキストファイル（unit.txt, pilot.txt, *.map等）のパーサー実装のための仕様書です。

## 共通仕様

### 文字エンコーディング
- **Shift-JIS** エンコーディング（UTF-8への変換が必要）
- `encoding-japanese` ライブラリを使用して変換

### コメント
- `#` で始まる行：コメント行として無視
- `//` 以降の文字列：コメント部分として無視

### 行の継続
- 行末に `_` を付けると次の行と連結される

### データ区切り
- `,` (カンマ) でフィールドを区切る
- `===` で武器データとアビリティデータの区切り

## ユニットデータ (unit.txt / robot.txt)

### フォーマット

```
名称
愛称, [読み仮名,] ユニットクラス, パイロット数, 最大アイテム数
移動可能地形, 移動力, サイズ, 修理費, 経験値
特殊能力
特殊能力名, ...
(または "特殊能力なし")
最大HP, 最大EN, 装甲, 運動性
地形適応, ユニットグラフィックファイル名
武器名, 攻撃力, 最小射程, 最大射程, 命中率, 弾数, 消費EN, 必要気力, 武器地形適応, クリティカル率, 武器属性 [<必要条件>] [(必要技能)]
...
[===]
[アビリティ名, 効果, 射程, 回数, 消費EN, 必要気力, アビリティ属性 [<必要条件>] [(必要技能)]]
...
```

### フィールド詳細

1. **名称**: ユニットの一意な名前（半角括弧のみ使用可、スペース・コンマ・セミコロン不可）
2. **愛称**: 表示用の名前（式置換 `$(変数名)` が使用可能）
3. **読み仮名**: ソート用（省略可、省略時は愛称から自動生成）
4. **ユニットクラス**: 分類名（括弧で囲むと人間ユニット扱い）
5. **パイロット数**: 1-99（括弧で囲むと特殊な動作）
6. **最大アイテム数**: 0-99
7. **移動可能地形**: `空`, `陸`, `水`, `地中`, `宇宙` の組み合わせ（例: `空陸`）
8. **移動力**: 0-99
9. **サイズ**: `XL`, `LL`, `L`, `M`, `S`, `SS`
10. **修理費**: 0-9999999
11. **経験値**: 0-9999
12. **特殊能力**: 複数行で指定可能
13. **最大HP**: 0-9999999
14. **最大EN**: 0-9999
15. **装甲**: 0-99999
16. **運動性**: 0-9999
17. **地形適応**: 4文字（空中・地上・水中・宇宙の順、例: `AACA`）
    - ランク: `S` > `A` > `B` > `C` > `D` > `-`
18. **ユニットグラフィックファイル名**: 32×32 BMP（例: `unit.bmp`, ない場合は `-.bmp`）

### 武器データ

各武器は1行で記述：

```
武器名, 攻撃力, 最小射程, 最大射程, 命中率, 弾数, 消費EN, 必要気力, 武器地形適応, クリティカル率, 武器属性 [<必要条件>] [(必要技能)]
```

- **攻撃力**: 0-99999
- **最小射程**: 通常は1
- **最大射程**: 1-99（1=格闘、2以上=射撃）
- **命中率**: -999 ~ +999（0の場合は `+0`）
- **弾数**: 1-99 または `-`（無制限）
- **消費EN**: 0-999 または `-`
- **必要気力**: 100-150 または `-`
- **武器地形適応**: 4文字（例: `AAAA`）
- **クリティカル率**: -999 ~ +999
- **武器属性**: `武`, `Ｂ`, `Ｐ`, `Ｍ全` など（複数指定可、例: `武Ｐ火`）

### アビリティデータ

`===` の後にアビリティを記述（省略可）：

```
アビリティ名, 効果, 射程, 回数, 消費EN, 必要気力, アビリティ属性 [<必要条件>] [(必要技能)]
```

## パイロットデータ (pilot.txt)

### フォーマット

```
名称
愛称, [読み仮名,] 性別, ユニットタイプ, 地形適応, 経験値
特殊能力
特殊能力名, 獲得レベル, ...
(または "特殊能力なし")
格闘攻撃力, 射撃攻撃力, 命中, 回避, 技量, 反応, 性格
SP, 最大SP, スペシャルパワー名, 獲得レベル, ...
(または "SPなし")
顔グラフィックファイル名, MIDIファイル名
[===]
[ユニットに付加する特殊能力名, ...]
[===]
[武器名, ...]
[===]
[アビリティ名, ...]
```

### フィールド詳細

1. **名称**: パイロットの一意な名前（`(ザコ)` または `(汎用)` 付加可）
2. **愛称**: 表示用の名前
3. **読み仮名**: ソート用（省略可）
4. **性別**: `男性`, `女性`, または `-`
5. **ユニットタイプ**: 操作可能なユニットクラス（スペース区切りで複数指定可）
6. **地形適応**: 4文字（空中・地上・水中・宇宙の順）
7. **経験値**: 0-9999
8. **特殊能力**: 複数行で指定、レベルと獲得レベルのペア
    - 例: `切り払いLv1, 1, Lv2, 18, Lv3, 35`
9. **格闘攻撃力**: 0-9999
10. **射撃攻撃力**: 0-9999（術・魔力持ちの場合は「魔力」扱い）
11. **命中**: 0-9999
12. **回避**: 0-9999
13. **技量**: 0-9999
14. **反応**: 0-9999（200以上で2回行動可能）
15. **性格**: `機械`, `弱気`, `普通`, `強気`, `超強気`
16. **最大SP**: 0-9999
17. **スペシャルパワー**: 名前と獲得レベルのペア
    - SP消費量カスタマイズ: `熱血=35, 9` (35SP, Lv9で習得)
18. **顔グラフィックファイル名**: 32×32 or 64×64 BMP（例: `pilot.bmp`, ない場合は `-.bmp`）
19. **MIDIファイル名**: BGM（例: `bgm.mid`, ない場合は `-.mid`）

## マップデータ (*.map)

### フォーマット

```
"MapData"
"Reserved"
幅,高さ
地形ID,ビットマップ番号
地形ID,ビットマップ番号
...
（幅×高さ 行繰り返し、X座標→Y座標の順）
["Layer"]
[上層地形ID,上層ビットマップ番号]
[上層地形ID,上層ビットマップ番号]
...
```

### フィールド詳細

1. **"MapData"**: 新形式マップの識別子（旧形式は20×20固定）
2. **"Reserved"**: 予約フィールド
3. **幅,高さ**: マップのサイズ
4. **地形ID**: 地形データの番号
5. **ビットマップ番号**: 地形画像のバリエーション
6. **"Layer"** (オプション): 上層レイヤーの開始マーカー
7. **上層地形ID**: 上層の地形ID（ない場合は `NO_LAYER_NUM`、通常は負の値や特定の値）
8. **上層ビットマップ番号**: 上層の画像番号

### データ構造

- マップセルは **幅×高さ** 個存在
- 読み込み順序：
  - X座標（1～幅）を固定して Y座標（1～高さ）をループ
  - つまり列優先（column-major）順

## パース時の注意点

### 1. エンコーディング処理

```typescript
import Encoding from 'encoding-japanese';

// Shift-JIS → UTF-8 変換
const detectedEncoding = Encoding.detect(buffer);
const unicodeArray = Encoding.convert(buffer, {
  to: 'UNICODE',
  from: detectedEncoding || 'SJIS'
});
const text = Encoding.codeToString(unicodeArray);
```

### 2. 行の処理

- 空行をスキップ
- `#` で始まる行をスキップ
- `//` 以降を削除
- 行末の `_` で次の行と連結

### 3. カンマ区切りのパース

- 引用符 `"` で囲まれた文字列内のカンマは区切り文字ではない
- トリム処理を忘れずに

### 4. 省略可能なフィールド

- ユニットデータの読み仮名
- パイロットデータの読み仮名、性別
- 武器・アビリティの必要条件・必要技能
- マップの上層レイヤー

### 5. エラーハンドリング

- 不正な形式の行をスキップまたは警告
- 未定義の地形IDなどの参照エラーを検出
- ファイルが存在しない場合の処理
